**Reading the raw Windows records.** Three of the `0a6ac3f` records, `cleanup-reconciliation-windows-11.json`, `group-state-cleanup-windows-11.json` and `opencode-cutover-windows-11.json`, are the bytes PowerShell wrote: UTF-8 with a leading byte order mark (U+FEFF) and CRLF line ends. They are kept exactly as collected, so their hashes still match the run, and they are archival evidence, not an interchange format. Read them with a BOM-aware decode, for example in Python `json.loads(path.read_text(encoding='utf-8-sig'))`; a reader that decodes plain UTF-8 and then parses the text rejects them with an unexpected-BOM error. Dropping only the leading U+FEFF in memory is enough, and the files are never edited. No gate reads these supplementary records, and the other nine files have no BOM.
