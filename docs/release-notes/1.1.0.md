## OpenCode installs from `@opencode/cli`

The agent `opencode` is installed from the npm package `@opencode/cli`, OpenCode's v2 distribution, instead of `opencode-ai`. The agent name `opencode`, its command, and `opencode auth login` do not change, and neither does anything `opencode proxy` writes.

- **Existing installations keep working.** The manager still recognizes an `opencode-ai` installation in a sandbox's home data as the managed one, under the checks it applies to every installation, and never installs `opencode-ai` again.
- **Migrating.** `sandboxed-agents agents update NAME opencode`, for an agent without a pin, and `sandboxed-agents agents enable NAME opencode --force` replace an `opencode-ai` installation with `@opencode/cli`. A bare `agents enable NAME opencode`, and `enable --force` on a healthy `@opencode/cli` installation, migrate nothing and need no registry. `update` without `--force` refuses while an `opencode` session runs; either command with `--force` stops that session first.
- **Your data stays.** The migration touches the installation and the agent selection only, not OpenCode's configuration, the proxy configuration, or a stored login. OpenCode 2.x reads the old configuration file itself and imports the old credentials into its own database.
- **Pins.** A pin to a version of `opencode-ai`, such as `1.19.5`, names no version of `@opencode/cli`. For `opencode`, a requested `--version`, even one equal to the installed version, and a recorded pin, when a command has to install again, are first checked with a read-only `npm view` of the published versions of `@opencode/cli`, run with the sandbox's npm configuration, before anything is installed. A pin that is not published is refused with guidance to run `agents update NAME opencode --unpin` or `agents enable NAME opencode --version VERSION` with a version that the message names. When the check cannot be made, the command is refused and changes nothing.
- **Install the new manager first.** The manager that handles these commands is part of a sandbox's image, and a sandbox keeps its image until `sandboxed-agents update NAME` runs. Run it after installing 1.1.0 and before the commands above.

The details are in [Agents](../agents.md#move-opencode-to-its-new-package). The `opencode proxy` workflow was tested offline on Linux x64 against OpenCode 2.3.0 with the repository's contract test; the commands, checksums, source reading, and limits of that test are in the [offline record](../validation/issue-165/offline.md). No run of OpenCode 2.3.0 inside a sandbox, on Windows, or on a live host is recorded.
