# sandboxed-agents 1.1.0

Version 1.1.0 follows [1.0.0](1.0.0.md) and adds the **proxy workflow**: a way to point an agent at a CLIProxyAPI server you already run. These notes describe what changed since 1.0.0. They are committed before the preview tag, so they are part of the commit that the gates validate; they say nothing about whether a gate has passed. A stable release states the commit each gate passed on in the release text below these notes, written by the release workflow ([Releases](../releases.md#stable-release-check)). A preview of this version, tagged `v1.1.0-preview.YYYYMMDD.N`, uses these notes unchanged and is a maintainer test build. What 1.0.0 contains, the platforms, the release files, and the install methods are unchanged; see the [1.0.0 notes](1.0.0.md).

## What changed since 1.0.0

- **Proxy workflow for four agents.** `agents login NAME AGENT proxy --url URL` points `claude`, `codex`, `copilot`, or `opencode` at a CLIProxyAPI server that you run and that the sandbox can reach. It reads a client API key from standard input only, so it needs no terminal, and writes the URL, the key, and a model selection into the agent's own configuration in the sandbox's home data, merging with and keeping every other setting. `--remove` deletes only what the workflow wrote and reads no key. The workflow installs and configures no server, signs in to no upstream account, and checks the key against nothing ([glossary](../../CONTEXT.md), [Sign in to an agent](../agents.md#sign-in-to-an-agent)).
  - **Claude Code** ([Claude proxy workflow](../agents.md#claude-proxy-workflow)): the URL and key go into its user settings file; `--model ID` is optional.
  - **Codex** ([Codex proxy workflow](../agents.md#codex-proxy-workflow), [codex-proxy.md](../codex-proxy.md)): a provider in `config.toml` plus the key stored by `codex login --with-api-key` in `auth.json`; `--model ID` is required. Codex keeps one stored login, so a ChatGPT login is replaced only with `--replace-login`. Because the workflow changes two files, it publishes them through a recovery directory under a new Codex configuration lock, refuses while a Codex run marker exists or a Codex agent session runs, and the `browser` and `device-code` workflows refuse while the proxy is configured. An interrupted change leaves a marker that blocks Codex use until you recover by hand ([recovery](../agents.md#recover-from-an-interrupted-codex-proxy-change)).
  - **OpenCode** ([OpenCode proxy workflow](../agents.md#opencode-proxy-workflow)): a custom provider in its configuration file, leaving provider login untouched; `--model ID` is required.
  - **Copilot CLI** ([Copilot proxy workflow](../agents.md#copilot-proxy-workflow)): a `cliproxyapi` provider and model entry in its provider registry, selected with `--model cliproxyapi/ID` and never made a default; `--wire-api completions|responses` chooses the wire API. It needs Copilot CLI 1.0.106 or newer and leaves the `device-code` login and the GitHub-hosted features that need it untouched.
- **Behavior change: `agents login` needs a workflow name for every agent.** In 1.0.0 `agents login NAME claude` ran `browser`, and likewise for `copilot` and `opencode`. No agent has exactly one workflow now, so the name is required: `agents login NAME claude browser`, `agents login NAME opencode provider`, and so on. Without it the command fails before Podman is called and lists the workflows. Options of the proxy workflow on any other workflow are a usage error.
- **Documented `shell` and `agents run` behavior.** The [command reference](../command-reference.md#running-programs-in-a-sandbox) and the quick guides now describe how `shell NAME` and `agents run NAME AGENT [ARG...]` treat standard input, terminals, arguments, and exit status, including how to feed `shell` commands from PowerShell. These are documentation changes of existing behavior.
- **Validation tooling.** A collector, `internal/validationduration/cmd/retain-durations`, derives a sanitized per-case duration file from a live-suite log without changing the schema 2 record or the release gate ([Retaining case durations](../images.md#retaining-case-durations)). The manual checklist and the maintainer notes gained the proxy items, the Copilot CLI floor test (`scripts/test-copilot-proxy.py`), and the manual-check runner's Windows installer-trace review script got a fix (`Review-InstallerTrace.ps1`). None of this changes the executable or the gates.
- **Dependency.** The executable now also depends on `github.com/pelletier/go-toml/v2`, for the Codex configuration.

## Platforms and requirements

Unchanged from 1.0.0: Linux amd64 with rootless Podman 4.4.0 or newer; Windows 11 x64 with Podman 4.7.0 or newer and a running rootless WSL2 machine; OpenSSH on both ([host prerequisites](../host-prerequisites.md)). A preview is installed from its release files; only a stable release is published to npm and NuGet ([Releases](../releases.md#versions)).

## Known limitations

[SECURITY.md](../../SECURITY.md) states the threat model and every limit; the limits in the [1.0.0 notes](1.0.0.md#known-limitations) still hold. In addition:

- A proxy workflow sends what the agent sends to the server you name, with the client key you gave it. The key is stored in the sandbox's home data like any other agent credential, and every agent in the sandbox can read it. The workflow cannot check the server, the key, or the model; the documented check for each agent is a run of that agent through `agents run`.
- The proxy workflows have offline coverage. The checklist items for the Claude, Codex, and OpenCode proxy workflows are not part of the manual-checklist record, and these notes claim no live result for any of the four workflows. The [manual checklist](../manual-checklist.md) and the [maintainer notes](../maintainers.md#live-runs-on-record) say what was observed and what was not.
- Codex's recovery after an interrupted proxy change, its refusal while the recovery directory exists, and the run-marker behavior are not checked on a live host ([Codex proxy workflow](../agents.md#codex-proxy-workflow)).
- The Copilot proxy workflow's 1.0.106 floor was tested against local fixtures, not against GitHub's service ([maintainer notes](../maintainers.md#copilot-cli-floor-of-the-proxy-workflow)).
